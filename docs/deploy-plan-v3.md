## 3. 실행 순서

### 0단계 · 사전 정리 (로컬, 운영 영향 없음)
1. **마이그레이션 파일 줄바꿈 복원** — 기존 4개 `.sql` + `migration_lock.toml`이 내용은 그대로인데 LF→CRLF로 바뀌어 있다. 이대로 `migrate deploy`를 돌리면 **checksum 불일치로 실패**한다.
   `git checkout -- prisma/migrations/20260324141032_* 20260328*/ migration_lock.toml`
2. **새 마이그레이션 보정** — 기본 파트명 규칙이 `기획팀→'기획'`만 있어 디자인팀이 `'디자인팀'`이 된다. 로컬과 맞게 `디자인팀→'디자인'` 추가.
3. 변경 파일 커밋 (앱 코드 + 마이그레이션 + 시드/이관 스크립트).

### 1단계 · 백업
```
pg_dump "$PROD_URL" -Fc -f backup/neon-YYYYMMDD-HHMM.dump
```
복원 경로까지 확인하고 넘어간다. 이 파일이 유일한 되돌리기 수단이다.

### 2단계 · 스키마 마이그레이션
```
DATABASE_URL="$PROD_URL" npx prisma migrate deploy
```
검증: Part/UserTeam 생성 · 기존 8명 UserTeam 자동 이관 · Category.partId·MajorCategory.partId backfill · **Report 38 / ReportItem 92 무변동**.

### 3단계 · 데이터 이관
- 로컬에서 이관 대상만 JSON 추출 → 운영에 **단일 트랜잭션**으로 적재.
- 매핑 키는 id가 아니라 **이름**(팀명, 팀+유저명, 파트/대분류/중분류명). 이미 있으면 건너뛴다(재실행 안전).
- 검증: 팀 11 / 유저 72 / 30주차 보고 46(운영 8 + 신규 47 = 55… 기존 8건 유지 + 47건 추가) / 기존 두 팀 아이템 수 불변.

### 4단계 · 코드 배포
`main` 푸시 → Vercel 자동 프로덕션 배포. `readyState=READY` + 커밋 SHA 일치까지 확인.

### 5단계 · 환경변수
현재 Vercel에는 `DATABASE_URL`, `CRON_SECRET`만 있다. 구글 4종이 없어 **전체취합본의 PDF·드라이브 내보내기가 눌렀을 때 에러**난다.
`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN` / `GDRIVE_ROOT_FOLDER_ID`를 **모두 sensitive**로 등록 후 재배포.

### 6단계 · 운영 점검
로그인(신규 1명 0000 → 변경) · 홈 3열 · 작성 화면(겸직 탭) · 팀 취합본 · 전체취합본(팀 필터/PDF/드라이브) · **기획팀·디자인팀 30주차 원본 그대로인지**.

## 4. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 마이그레이션 checksum 실패 | 0단계에서 줄바꿈 복원 (선행 필수) |
| 기존 두 팀 데이터 훼손 | 이관 스크립트가 기획팀·디자인팀 id를 **쓰기 대상에서 원천 제외**. 사후 카운트 대조 |
| 이관 중 실패 | 단일 트랜잭션 → 전량 롤백. 그래도 안 되면 1단계 덤프 복원 |
| 배포 사이 공백 | 순서를 DB→데이터→코드로. 구코드는 컬럼 추가만으로는 깨지지 않음 |
| 신규 64명 초기 비번 노출 | 전원 `NOT_SET`(0000) + `mustChangePw=true`. 최초 로그인 시 변경 강제 |
